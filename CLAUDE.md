# CSharpGame: a learning-oriented 2D game engine in C# (3D-ready)

Windows, .NET 10, Silk.NET (OpenGL 3.3 core), custom sparse-set ECS, Dear ImGui debug UI.
Goal: learn how engines work, so write core systems from scratch and use libraries only for plumbing. First game: a platformer. Status: phases 1-19 done (the 10-phase engine roadmap, the phase 11 polish pass, the phase 12 editor, the phase 13 3D foundation: meshes, materials, camera, lights, glTF models, box physics, the phase 14 transform hierarchy, the phase 15 3D editor view, the phase 16 3D physics stage 2: body-vs-body, capsules, character controller, oriented boxes, the phase 17 3D rendering depth: PBR, shadows, instancing, transparency, glTF animation, the phase 18 content pipeline: tile flip flags, animated tiles, parallax, Tiled import, tile brushes, History window, save-as-prefab and revert-to-prefab, and the phase 19 depth: HDR, MSAA, pixel-perfect, 2D light shadows, audio mixer/positional/streaming; per-camera effects and cached chunk meshes were deferred); what comes next is listed in `.claude/knowledge/tasks.md` (see `.claude/knowledge/features.md`).

## Projects

- `src/Engine.Core`      ECS, fixed timestep, `Transform` and `Parent` (`Hierarchy/TransformHierarchy`: world matrices from parent chains), input state and action map, asset manager. No GPU or window dependencies; unit-testable.
- `src/Engine.Platform`  Silk.NET window, GL context, input adapter, ImGui controller.
- `src/Engine.Rendering` Shader, Texture2D, SpriteBatch, Camera2D, `Sprite` component, `SpriteRenderSystem`, `TextureLoader`; `RenderTarget`, `PostProcessChain` and the effects (`ColorGradeEffect`, `VignetteEffect`, `BloomEffect`); `Light2D` and `LightingEffect`.
- `src/Engine.Physics2D` AABB, tile grid, swept collision solver, `PhysicsSystem`, moving platforms that carry riders, platformer controller (coyote time, jump buffering, variable jump). No GPU or window dependencies.
- `src/Engine.Tilemaps`  Chunked `TileLayer`, `TileSet` atlas, `TileGridBuilder` (layer -> physics grid), `TileLayerRenderSystem`.
- `src/Engine.Rendering3D` `Mesh`/`MeshData`/`MeshBuilder`, `Material` (PBR), `Camera3D`, `FlyCamera`, `OrbitCamera`, `Frustum`, `MeshRenderer`, `ModelRenderer`/`Model` (glTF/glb through `Gltf/GltfImporter`, with skins and animations), `ModelAnimator`/`ModelAnimationSystem`/`AnimatedPose`, `DirectionalLight`, `PointLight3D` and `MeshRenderSystem` (depth-tested PBR with instanced draws, sorted transparency and a sun shadow map). Depends on Core and Rendering (Shader, Texture2D).
- `src/Engine.Physics3D` `Aabb3`/`Obb3`, `CollisionSolver3D` (swept boxes and raycasts), `Sat`, `CapsuleCollision`, `PhysicsSystem3D`, `CharacterControllerSystem3D`, `BoxCollider3D`, `CapsuleCollider3D`, `PhysicsBody3D`, `StaticSolid3D`, `CharacterController3D`. Own 3D physics, stage 2: swept boxes against static solids and each other (mass-weighted pushing, stacking), capsule and sphere bodies that slide, a character controller, oriented static boxes (ramps) via SAT. No rigid-body rotation. No GPU or window dependencies; mirrors Physics2D.
- `src/Engine.Animation` `AnimationClip`, data-driven `AnimationStateMachine`, `SpriteAnimator` component, `AnimationSystem`.
- `src/Engine.Scenes`    JSON scenes and prefabs: `ComponentRegistry`, `SceneSerializer`, `Prefab`, `JsonMerge`. Depends on Core only.
- `src/Engine.Audio`     `AudioClip`, `WavDecoder`, `IAudioDevice` (`OpenAlAudioDevice`, `NullAudioDevice`), `VoicePool`, mixer groups (`AudioMixer`, `AudioGroup`), positioned sounds (`Spatialization`), streams (`IAudioStream`, `WavStream`), and the `AudioSource` / `AudioListener` components with `AudioSourceSystem`. Depends on Core and Silk.NET.OpenAL only; no window or GL.
- `src/Engine.Runtime`   `Game` base class and loop, debug overlay, entity inspector and profiler panel (`Inspector/`), scene editor (`Editor/`), `EngineComponents` (registers every engine component), `Game.Scenes`, `Game.Audio`, `Game.Profiler`. Composition root: the only module allowed to depend on every engine module; it also registers all asset loaders.
- `samples/Scene3D`     The 3D sample: a lit room loaded from JSON (scene, materials) plus procedural meshes, viewed with a fly camera.
- `samples/Platformer`   The first game (playable v1: coins, exit, creatures, lives, HUD), almost entirely data: scene, prefabs, tile layers, tile set and animation graphs are JSON under `Assets/`; rules live in `GameSession` and `InteractionSystem`.
- `tests/`               xUnit v3 tests (Microsoft.Testing.Platform, see `global.json`), one project per module (`Engine.<Module>.Tests`).
- `tools/`               PowerShell scripts to run, drive and screenshot the sample (see `tools/README.md`).

Dependency direction: samples -> Runtime -> (Core, Platform, Rendering, Rendering3D, Physics3D, Scenes, Physics2D, Tilemaps, Animation, Audio); Tilemaps -> (Core, Rendering, Physics2D); Animation -> (Core, Rendering); Rendering3D -> (Core, Rendering); Physics3D -> Core; Rendering, Platform, Physics2D, Scenes and Audio -> Core. Core never references any other module or Silk.NET; Physics2D never references Rendering or Tilemaps; Scenes knows no component types (Runtime registers them).

## Standing rules

- **Search for an existing implementation before creating a new one** (type, helper, system, test fixture). Extend or reuse; do not duplicate.
- **One type per file**, named after the type. *(Build error: SA1402.)*
- **XML-document everything public/protected**: purpose and why, not just the name. *(Build error: CS1591.)*
- **Split big classes into partial files** `Type.Topic.cs` (past ~150 lines or mixed topics); extract a collaborator when a responsibility is separable.
- **SOLID.** Depend on abstractions at layer boundaries (input, rendering, audio, physics); no Silk.NET types in game or Core code; small interfaces; extend by adding systems/components, not by editing switches.
- **Components are plain data structs**; behaviour lives in systems. Components reference assets by `AssetHandle<T>`, never by the loaded object.
- **3D-ready math**: `Vector3`/`Quaternion`/`Matrix4x4` for transforms (Z = draw order in 2D).
- **No allocation in per-frame/per-entity paths** (no LINQ, no per-frame capturing closures).
- **Structural ECS changes during a query** go through `CommandBuffer`.
- **Input**: ask `ActionMap` for intent, never a physical key. Read edges (pressed/released) in per-frame code and latch into components; never in fixed-step systems.
- **Physics**: order fixed systems as `PreviousTransformSystem`, `MovingPlatformSystem`, then "decide velocities" (patrol, `PlatformerControllerSystem`), then `PhysicsSystem`. Gameplay reads `PhysicsBody.Contacts`/`IsGrounded`. Touching edges never count as overlap (epsilon); a body spawned *inside* a solid passes through it, so spawn clear of solids.
- **Tilemaps**: tile id 0 = empty, 1+ index a `TileSet` (row-major, 1-based); solidity lives on the tile set and collision is derived with `TileGridBuilder`, never hand-built twice. Draw order: background `TileLayerRenderSystem` -> `SpriteRenderSystem` -> foreground `TileLayerRenderSystem`.
- **Animation**: gameplay writes animator *parameters* (`SpriteAnimator.SetParameter`); the state machine picks the clip. Run the parameter-writing system before `AnimationSystem`, both per frame. Create animators with `SpriteAnimator.Create`.
- **Scenes and prefabs**: a component is saved only if registered (`Components.Register<T>("Name")`, in the game's constructor for game components); register it **and** keep it plain public-field data. An entity made from a prefab carries a `PrefabLink` and saves as prefab + overrides. Files reference assets by *name*, never id; prefab overrides are JSON merge (objects merge, arrays replace, `null` removes a component). Loading is all-or-nothing: parse first, create entities after. Do not store `Entity` references in saved components (not remapped on load yet). New asset kinds that scenes refer to need an `IAssetLoader<T>` registered in `Game.OnLoad`.
- **Game rules**: keep the rules and score in a plain class with no engine types (`GameSession`) and unit-test it; a system only detects overlaps and reports events to it (`InteractionSystem`); the game class wires sounds, HUD and restart. Player-facing UI goes in `Game.Hud()` (always drawn), debug panels in `DebugGui()` (hidden by F1). Reference: `samples/Platformer/GameSession.cs`.
- **Post-processing and lighting**: the scene is drawn through `Game.PostProcess` (`BeginScene`/`EndScene` wrap `Draw` and the render systems); add effects in `Load` (`PostProcess.Add(new BloomEffect(Gl))`), lighting first so the glow can bloom. A new effect derives from `SinglePassEffect` (one fragment shader, settings as public properties, which the "Post effects" panel edits by reflection) or implements `IPostEffect`. Lights are `Light2D` components (saved in scenes); walls that block them are `ShadowCaster2D` boxes or tile layers with `CastsShadows` (add `new TileShadowCasterSource(World, Assets, RenderClock)` to `LightingEffect.ShadowSources`); a light only casts shadow from walls facing away from it. Effects own GL objects: they are disposed by the chain in `Game`'s `Closing` handling. With no effect enabled and no scene setting on, the scene draws straight to the window. Scene settings on the chain: `Hdr` (add a `ToneMapEffect` last), `Samples` (MSAA) and `SetPixelPerfect(w, h)` (set the camera `ViewportSize` to the same size and `PixelSnap = true`; map the mouse with `PixelPerfectLayout.WindowToGame`). Effects never draw into the scene target: the chain gives them ping-pong targets.
- **Render interpolation**: moving entities carry a `PreviousTransform` (recorded by `PreviousTransformSystem`, which must be the first fixed system); render systems take `Game.RenderClock` and draw between the last two steps. Anything that follows a moving entity at render time (camera, lights) must use `PreviousTransform.Interpolate` too, and do it in `Draw`, after the fixed steps, never in `Update`.
- **Profiling**: systems are timed automatically (`SystemGroup.Profile`); time your own work with `Profiler.GetSection` once (keep the id) then `Begin`/`End` per use. Never look sections up by name per frame.
- **Audio**: game code plays sounds through `Game.Audio` (`IAudioDevice`), never OpenAL types (mixer groups: `Audio.Mixer`; an entity plays through an `AudioSource` component driven by `AudioSourceSystem`, which a game adds to `FrameSystems` with `new AudioSourceSystem(Audio, Assets)`; positioned sounds need mono clips and an `AudioListener` entity; music is a `WavStream` passed to `Audio.PlayStream`); load clips with `Assets.Load<AudioClip>("sounds/x.wav")` and `Audio.Preload` them in `Load`. A missing sound card falls back to `NullAudioDevice` (visible in the overlay), never a crash.
- **Inspector**: it edits registered components by reflection over their public fields, so keep component fields to simple types (numbers, bools, strings, enums, vectors, `Color`, `Rect`, `AssetHandle<T>`, nested plain structs); anything else shows read-only. Pass `defaultValue` to `Register<T>` when `default(T)` is invalid.
- **Shutdown**: free GPU resources in `Unload`/the window `Closing` event, while the GL context still exists (`Game` then disposes `Audio`, the `PostProcess` chain, then `Assets`). Never touch GL from `Dispose` or after `Run()` returns.
- **Render stats**: call `SpriteBatch.ResetStats()` once per frame (in `Draw`) because a frame has several batch passes.
- **GPU resources** are `IDisposable`, owned by exactly one object; create in `Load`, dispose in `Unload`; `Game.Assets` disposes loaded assets.
- **Asset hot-reload**: look assets up through their `AssetHandle<T>` at the time of use (do not cache the loaded object across frames), or they will not see a reload; override `Game.HotReloadRoot` to watch the project asset folder.
- **Scene editor**: F2 (`Game.IsEditing`) freezes the game like pause; override `Game.SceneCamera`, `ScenePath` and `SceneReloaded` to give the editor a scene view and Save/Reload, and make the game's own update (and camera follow) stop while `IsEditing`. Every editor change goes through a command (`Editor/Undo`: `Execute` to do-and-record, `Push` for a live gesture recorded when it ends) and refers to entities by tracked id, never by `Entity`; anything that moves an entity must clear its `PreviousTransform` (`EditContext.SetComponent` does). Editor logic that can be pure (picking, gizmo maths, camera controls, cloning) stays free of ImGui and is unit-tested. A game with a 3D camera overrides `Game.SceneCamera3D` and gets an orbit camera, mesh-bounds picking and the gizmo; it must stop applying its own camera while `IsEditing` and take the view back with `FlyCamera.CopyFrom`. The gizmo (`Editor/Gizmos`: `TransformGizmo`, `GizmoApply`) works through `IGizmoView` for both cameras and edits every selected entity (`EditorSelection`) as one undo step; the scene still draws to the whole window (no docked viewport).
- **3D rendering**: world is right-handed, Y up, the camera looks down its local -Z. Matrices are row-vector `Matrix4x4`, uploaded untransposed (GLSL `matrix * vector`). Use `Projection3D.Perspective` (OpenGL depth -1..1), never `Matrix4x4.CreatePerspectiveFieldOfView` (Direct3D 0..1). `MeshRenderSystem` goes in `RenderSystems` before the 2D passes; it clears depth itself, so the game's `Draw` only clears colour. Meshes, materials and models are assets (`Assets.Add("meshes/cube", new Mesh(Gl, MeshBuilder.Cube(...)))`, `.material.json`, `.gltf`/`.glb` through `Assets.Load<Model>`), components hold handles. glTF is flattened for drawing (each primitive becomes a part with its node matrices multiplied in) but the node tree is kept in `ModelData.Nodes` for posing (`ModelPose`). Materials are metallic-roughness (PBR): `roughness`/`metallic` (not shininess), maps, `alphaMode` opaque/mask/blend; unknown keys in a `.material.json` throw. Share one `ModelPoses` between `ModelAnimationSystem` (a frame system) and `MeshRenderSystem` (its `poses` argument) to animate models (`ModelAnimator` component); identical mesh and material pairs are drawn instanced, blended materials after the opaque ones, farthest first; the sun casts a shadow map (`Lighting3D.ShadowsEnabled`/`ShadowDistance`/`ShadowBias`; set `ReflectedSky` near your clear colour so metals have something to reflect). Winding is counter-clockwise seen from outside (back faces are culled). Lighting is in linear colour: textures and colours are decoded from sRGB in the shader and encoded again.
- **Transform hierarchy**: an entity with a `Parent` has a *local* `Transform`; without one it is world space as always. Never hand-multiply: ask `TransformHierarchy` (`GetWorldTransform`, `GetWorldPosition`, `GetRenderTransform`/`GetRenderMatrix` which also interpolate every level, `ToLocal`) and change the tree only through `SetParent` (refuses loops; `keepWorld` rewrites the local transform) and `Destroy` (whole subtree). Render systems (sprites, lights, meshes) and static solids honour parents; tile layers and `PhysicsBody`/`PhysicsBody3D` entities must be roots (bodies throw otherwise). `Parent` is not a registered component: scenes store `"parent": <index of another entry>`. Editor commands refer to parents by tracked id (`EntitySnapshot`, `ReparentCommand`, `CompositeCommand` for subtrees).
- **3D physics**: order fixed systems as `PreviousTransformSystem`, `CharacterControllerSystem3D` (if the game has characters), then `PhysicsSystem3D` (after anything that sets velocities). Static geometry is a `BoxCollider3D` + `StaticSolid3D` entity; the collider box ignores the transform's scale (its size is its own field) and its rotation unless `Oriented` is set on a static solid (ramps). A moving body has a `PhysicsBody3D` plus a box or a `CapsuleCollider3D` (never both; a sphere is a capsule as tall as wide), is a root, and collides with the other bodies (mass-weighted pushing, stacking); a walkable character adds a `CharacterController3D` and the game only writes its `Move`/`JumpPressed` intent per frame. Gameplay reads `PhysicsBody3D.Contacts`/`IsGrounded` and casts rays with `PhysicsSystem3D.Raycast(Ray, ...)` (the same `Engine.Core.Ray` as `Camera3D.ScreenPointToRay`). Same sweep rules as 2D: touching faces are not overlap, and a body spawned inside a solid passes through it, so spawn clear of solids.
- **Pause**: `Game.IsPaused` freezes `FrameSystems`, `FixedSystems` and the timestep, while `Update`, drawing and `Hud()` keep running; game code that advances its own clocks (`GameSession.Tick`) must skip itself while paused. `Game.Quit()` closes the window.
- **Logging**: record events through `Game.Log` (`Logger`: `Info`/`Warning`/`Error`, short category), never `Console.WriteLine`; it also feeds the in-game Log window. Never in per-frame/per-entity paths, and logging does not replace throwing.
- **Fail loudly** with specific guard-clause exceptions; never swallow exceptions.
- **Gotchas**: `Matrix4x4` is row-vector/row-major, upload to GL **without transposing**; `default(Transform)` is invalid, use `Transform.Identity`/`At`; use binary-exact floats in timing tests.
- Verify rendering and input changes in the real window with `tools/` (unit tests do not cover GL code).

## Keeping this context current

In any change that alters the data schema, adds, removes, or renames a project or module, moves a feature to different code, or makes an architecture decision, update CLAUDE.md and the files in `.claude/knowledge/` in the same change, without being asked.
