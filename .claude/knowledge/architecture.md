# Architecture

Learning-oriented 2D game engine in C# (.NET 10, Windows), designed so 3D can be added later. Goal: understand how engines work, so core systems are written from scratch and libraries are used only for plumbing (windowing, GL bindings, image decoding, debug UI).

## Projects and dependencies

```
samples/Platformer ──► Engine.Runtime ──► Engine.Rendering ──► Engine.Core
        │                   │                                     ▲
        │                   └──────────► Engine.Platform ─────────┤
        ├──► Engine.Physics2D ────────────────────────────────────┤

        ├──► Engine.Audio ──► Engine.Core

```

Rules: Core never references Platform, Rendering or Silk.NET. Layers depend on abstractions at their boundaries (input is `InputState`/`ActionMap`, not Silk types).

Shared build config is in `Directory.Build.props` (net10.0, nullable, implicit usings; for non-test projects XML docs + StyleCop `SA1402`, with `CS1591` and `SA1402` as errors). Analyzer severities are in `.editorconfig`.

## Frame data flow

Per display frame (`Game.OnUpdate` then `Game.OnRender`, driven by Silk's window loop):

1. Window events fill `InputState` (via `SilkInputAdapter`; key/mouse presses are dropped while ImGui wants the input, releases always pass).
2. `FrameSystems` run, then `Game.Update` (read input here, latch intent into components, e.g. `PlayerInputSystem` writes `PlatformerIntent`).
3. `FixedTimestep.Advance(dt)` returns N steps; for each: `FixedSystems`, then `Game.FixedUpdate`. The sample's first fixed system is `PreviousTransformSystem` (records each `PreviousTransform` before the step moves anything).
4. `Input.EndFrame()` clears pressed/released edges and scroll.
5. Render: `Game` sets `RenderClock.Alpha` (the timestep's 0..1 fraction), then `PostProcess.BeginScene()` (redirects drawing into the scene target only if some effect is enabled), `Game.Draw` (resets batch stats, clears), `RenderSystems` in registration order (sample: background/ground `TileLayerRenderSystem`, `SpriteRenderSystem` which gathers `Transform`+`Sprite` and sorts back-to-front by Z then texture, foreground `TileLayerRenderSystem`; each pass is its own `SpriteBatch.Begin/End`), then `PostProcess.EndScene()` (runs the enabled effects, the last one writing to the window), then the ImGui overlay (`DebugOverlay` + `Game.DebugGui`), which is drawn after the effects so tools are never darkened or bloomed.

Shutdown: GPU cleanup happens in the window's `Closing` event, **while the GL context still exists**: `GameWindow.OnClosing` raises `Closing` (so `Game` runs `Unload()` then `Assets.Dispose()`), then disposes the ImGui controller and input. `Game.Dispose`/`GameWindow.Dispose` afterwards only release the managed GL bindings and the window. (Decision and reason: after `Run()` returns the context is destroyed and any GL delete throws `NoContext`; this crashed every normal window close until phase 7.)

## Scene editor (`src/Engine.Runtime/Editor`)

F2 toggles `SceneEditor` (internal, owned by `Game`; `Game.IsEditing`). While on: `FrameSystems`, `FixedSystems` and the timestep are frozen exactly as with `IsPaused`, and `RenderClock.Alpha` is forced to 1 (a frozen simulation must draw its real state: a stale fraction would leave moved entities part-way back). The window gets a menu bar (File: Save scene Ctrl+S / Reload / Close; Edit: New, Duplicate Ctrl+D, Delete Del), a `DockSpaceOverViewport` with a pass-through central node (docking is switched on in `GameWindow.OnLoad`), the `HierarchyPanel`, and the inspector's details in its own window (`EntityInspector.DrawDetailsWindow`; the hierarchy and inspector share one selection, `EntityInspector.Selected`).

- **Rendering is untouched**: the game still draws to the whole window and editor windows float over it or dock to its edges, so the scene is not reflowed into a viewport panel. Decision: a framebuffer "game view" panel is bigger work (render target, input remapping) and the foundation does not need it. The default layout is just first-use positions; `imgui.ini` remembers what the user docks (ImGui.NET does not expose `DockBuilder`).
- **Scene view input** (`SceneEditor.Viewport.cs`) reads ImGui's mouse (so `io.WantCaptureMouse` cleanly separates UI from scene): left-click picks, a click on the gizmo starts a drag, middle-drag pans, wheel zooms about the cursor, Ctrl snaps to 8 units. Ctrl is read from `IsKeyDown(LeftCtrl/RightCtrl)`, not `io.KeyCtrl`, which lags a frame behind a quick chord. The selection outline and gizmo are drawn on ImGui's background draw list (over the scene, under the windows).
- **Pure, unit-tested logic**: `EntityPicking` (sprite quad hit test with pivot, scale and rotation; topmost Z, then smaller quad; sprite-less entities hit within 12 screen px; tile layers never picked), `MoveGizmo` (handle hit test in screen space, drag maths in world space, axis constraint, snap), `EditorCameraControls` (pan, zoom about a point, clamp), `EntityCloner` (duplicate via the boxed component API; copy is offset, renamed " (copy)", with no render history).
- **What the game provides** (`EditorHooks`, filled from `Game`'s virtual members): `SceneCamera` (null = panels only, no scene view), `ScenePath` (null = Save/Reload disabled) and `SceneReloaded()` (re-find what was cached from the old world, as after a quick-load; the sample's `AfterWorldReplaced`). A game's own update code must stop while `IsEditing` (the sample returns early from `Update` and skips the camera follow).
- **Moving an entity** also clears its `PreviousTransform` (see above), so it is drawn where it is.
- **Undo/redo** (`Editor/Undo`, pure and unit-tested): `CommandStack` (undo list + redo list, capacity 256, a new change clears redo) of `IEditCommand`s (`Do`, `Undo`, `Description`, `Affected`): `SetComponentCommand` (before/after boxed values), `AddComponentCommand`, `RemoveComponentCommand`, `EntityLifetimeCommand` (create or delete, via `EntitySnapshot`). Decisions: (1) commands store a **tracked id** (`EntityTracker`), never an `Entity`, because undoing a delete creates a new entity whose generation differs; the tracker is re-bound to the new handle so older commands about it (a move made before the delete) still resolve; (2) live gestures are recorded once, when they end: the gizmo captures the transform at drag start and `Push`es a `SetComponentCommand` at mouse-up, the inspector remembers the value before the first change of a gesture (`PendingEdit`) and commits when no ImGui item is active any more, so a whole drag or typed name is one step; `Push` records an already-applied change, `Execute` does and records; (3) `EditContext.SetComponent` clears `PreviousTransform` on any Transform write, so undo cannot leave an entity drawn part-way; (4) the history is cleared whenever the editor is toggled and on Reload, because the game runs freely while the editor is off and Reload makes every handle stale; (5) the inspector records only while `EntityInspector.History` is set (editor on), so the F1 debug inspector stays a plain live editor; (6) undo is ignored while a drag or text field is active. Ctrl+Z undoes, Ctrl+Y or Ctrl+Shift+Z redoes, both also in the Edit menu with the step's description; after undo/redo the entity the step touched is selected (or nothing, if it no longer exists).
- **Play / Stop** (F3 or the menu bar button): `Play` takes `Scenes.Save()` as an in-memory snapshot (`EditorHooks.Snapshot`), clears the undo history, and lets the game run for real inside the editor (`Game.IsEditing` is false while playing, `Editing = Active && !Playing`); the hierarchy and inspector stay visible and editable as live tweaks (not undo steps), while File/Edit and the scene view's picking, gizmo and pan/zoom are disabled. `Stop` does `World.Clear()` + `Scenes.Load(snapshot)` + `SceneReloaded()`, clears the history again (every handle is stale) and calls `PlayStopped`; turning the editor off while playing stops first. The game gets `PlayStarted()` / `PlayStopped()` hooks (the sample begins a fresh run both times: new `GameSession`, start point from the hero, fresh door). Decisions: snapshot through the scene serializer rather than a second world, because it already round-trips every registered component and is what Save and quick-save use; the shortcut is F3, not a Ctrl chord, because Ctrl+P also reaches the game while it plays (the sample's pause key); only registered components survive Play/Stop, so unregistered runtime-only data is lost.
- **Tile painting** (`Editor/Tiles`): select a tile layer entity, switch Paint mode on (B or the "Tiles" window checkbox) and the mouse paints the palette tile (left) or erases (right); the cell under the cursor is outlined. `TileCells` (world point to cell given the layer entity position and tile size, cell bounds, Bresenham `Line` so fast drags leave no gaps), `TilePaintStroke` (changes the layer live, remembers each cell original id once) and `PaintTilesCommand` (before/after per cell) are pure and tested; `TilePainter` is the ImGui half (palette drawn from the tile set atlas texture, mouse handling, cursor). A stroke is one undo step, recorded when the button is released and tied to the layer it started on even if the selection changes. Decisions: tile layers are shared **assets**, not entities, so the command holds the `TileLayer` itself and `EditContext.DirtyTileLayers` tracks unsaved ones; Save writes each dirty layer with `TileLayerJson.Write` to `Game.EditableAssetPath(name)` (default: the asset root; the sample points it at the project `Assets/` folder like the scene); layer edits are not rolled back by Reload or Stop (they live in the asset, not the world snapshot), so painting then Play then Stop keeps the paint. Collision: `CollisionSolver.Grid` / `PhysicsSystem.Grid` are settable, and the sample rebuilds its grid from the edited ground layer in `StartFreshRun` (Play and Stop), because physics holds a grid built once at load.
- **Hot-reload with the editor**: saved tile layers are passed to `EditorHooks.AssetWritten` so the watcher does not reload the file the editor just wrote.
- **Known limits**: Save writes the whole live world through `SceneSerializer`; prefab instances are written as prefab + overrides (see Scenes), so a saved level stays lean, but whatever runtime state the simulation had written into components before the editor was opened (animation state, contacts, `PreviousTransform`) is saved too, so open the editor early; the sample saves to `Assets/scenes/level.scene.json` in the project tree when run from a build inside it (the next build copies it to the output folder), else to the copy beside the exe; no rotate/scale gizmos, no multi-select, flat hierarchy (no transform parents yet).

## 3D rendering (`src/Engine.Rendering3D`)

- **Pipeline per frame**: `MeshRenderSystem` (a render system, added before the 2D passes) gathers lights, clears the depth buffer, enables depth test (`Less`) and back-face culling per material, then queries `Transform` + `MeshRenderer`; for each entity it builds the model matrix (`ModelMatrix.From`: scale, rotate, translate), frustum-culls the mesh's bounding sphere (`Frustum`, radius scaled by the largest axis scale), picks up to 8 point lights that reach it (`PointLightSelector`), and draws. Depth test and culling are switched off afterwards so sprites, tiles and the HUD drawn later land on top. Entities with a `PreviousTransform` are interpolated like sprites. No sorting, no transparency, no instancing yet (one draw call per mesh).
- **Depth buffer**: the window asks for 24 depth bits (`GameWindow`), and `RenderTarget` has an optional depth renderbuffer; `PostProcessChain` gives only its scene target (target 0) one, because that is where the scene is drawn when an effect is on. Verified in the window with the vignette on and off.
- **Conventions and decisions**: (1) `Projection3D.Perspective` is written for OpenGL's clip depth (-1..1): `Matrix4x4.CreatePerspectiveFieldOfView` targets Direct3D (0..1), which would leave the near plane inside the volume and halve depth precision. (2) The shader multiplies `uModel * vec4(p, 1)` because row-major `Matrix4x4` memory read as column-major GL is the transpose. (3) The normal matrix is the inverse transpose of the model matrix (`ModelMatrix.NormalMatrix`), so non-uniform scale does not skew lighting. (4) Lighting is Blinn-Phong in linear light: base colour and texture are decoded with gamma 2.2, lit, then re-encoded, so two lights add energy correctly; ambient is a constant colour (`MeshRenderSystem.Lighting.Ambient`). (5) One `DirectionalLight` (the first found; it shines along the entity's forward -Z) and any number of `PointLight3D` (smooth falloff `(1 - (d/r)^2)^2`, zero at the radius); the shader takes at most 8 per draw and the CPU chooses the best ones per mesh. Lights are components, so scenes save them and the inspector edits them. (6) `Material` is a shared asset (colour, optional texture handle, shininess, specular, unlit, double-sided) loaded from `.material.json` by `MaterialLoader`; meshes are procedural (`MeshBuilder`) and added to `Assets` by the game under the names its scene files use, the same pattern as tile layers, until the glTF loader exists. (7) `Texture2D` gained `TextureFilter.Trilinear` (mipmaps) and `SetRepeat()` because 3D surfaces tile and are seen at grazing angles; sprite textures keep clamp and nearest.
- **Not yet**: shadows, normal maps, transparency and draw sorting, instancing, a 3D editor view (the editor's scene view is 2D: panels, hierarchy and inspector work on 3D entities, but there is no 3D gizmo or picking; `Camera3D.ScreenPointToRay` and `Ray` are the first building blocks), transform parents.

## Render interpolation

Fixed steps and display frames do not line up, so drawing the raw simulated position makes motion judder. Entities with a `PreviousTransform` are drawn at `Lerp(previous, current, alpha)` (`PreviousTransform.Interpolate`; scale is not blended). Decisions and reasons: (1) it is an opt-in component rather than a second copy of every `Transform`, so static entities pay nothing; (2) `default` means "no history", so a spawn, respawn or scene load draws at the real position instead of sweeping in from the origin; (3) `RenderClock` (set by `Game` before `Draw`) is handed to the render systems by constructor, not read from a global, and the parameter is optional so systems without it draw the raw state; (4) the camera follow runs in `Game.Draw` (after the steps, with the current alpha) on the interpolated hero position, otherwise it chases a position the sprite is not drawn at and jitters; (5) `LightingEffect` interpolates lights the same way so the lantern stays on the hero.

## ECS (`src/Engine.Core/Ecs`)

- `Entity` = (Id, Generation); generation 0 is `Entity.Null`. `EntityAllocator` hands out ids and bumps generations on destroy so stale handles fail `IsAlive`.
- `World` (partial: `World.cs` lifetime, `.Components.cs`, `.Queries.cs`, `.Internals.cs`) owns one `ComponentPool<T>` per component type, stored in a `Dictionary<Type, IComponentPool>`.
- `ComponentPool<T>` is a sparse set: `_sparse[entityId] = denseIndex + 1`, packed `Dense`/`Components` arrays, swap-remove.
- Queries (`Query<T1>`, `<T1,T2>`, `<T1,T2,T3>`) pass components by `ref`; they take an iteration lock so `Create/Destroy/Add/Remove` throw mid-query. Use `CommandBuffer` to defer, `Set` to overwrite existing components safely.
- Systems implement `ISystem.Update(World, double dt)`; `SystemGroup` runs them in insertion order. `Game` exposes three groups: `FixedSystems`, `FrameSystems`, `RenderSystems`.

## Physics (`src/Engine.Physics2D`)

- **Per fixed step** (`PhysicsSystem`): for each `Transform`+`PhysicsBody`+`BoxCollider`: apply gravity (`PhysicsSettings.Gravity`, `GravityScale`, clamp to `MaxFallSpeed`), sweep X then Y with `CollisionSolver.Sweep` (zero the blocked velocity component, snap to the face), then probe a 0.01 skin in four directions to set `PhysicsBody.Contacts` (so contacts persist while resting against a surface, even with zero velocity or zero gravity).
- **Solids**: `TileGrid` (cell (0,0) bottom-left, outside = empty) plus `StaticSolid`-tagged `BoxCollider` entities gathered each step (brute-force list; a spatial hash is deferred until static box counts justify it).
- **Sweep algorithm**: per axis, find the nearest obstacle face ahead of the leading edge across the box's extent on the other axis (shrunk by `Epsilon` = 0.001 so touching is not overlapping); obstacles already behind the leading edge are ignored, so overlapping a solid lets a body leave it but also lets a body spawned inside pass through. Tunnelling-proof for any speed.
- **Platformer controller**: input layer writes `PlatformerIntent` per frame (`MoveX`, `JumpHeld`, sticky `JumpPressedPending`); fixed-step `PlatformerControllerSystem` (before `PhysicsSystem`) converts the pending flag to a jump buffer, tracks coyote time from last step's `Below` contact, accelerates toward target speed (ground/air), jumps when buffer and coyote are both positive, cuts the jump when released early, and raises gravity scale while falling. Tuning (`PlatformerTuning`) and timers live in one `PlatformerController` component (the ECS supports queries of up to 3 components).
- **Moving platforms**: `MovingPlatform` (path `Travel`, `Speed`, runtime `Distance`/`Returning`, `default` is valid) on an entity with `BoxCollider` + `StaticSolid`; `MovingPlatformSystem` (fixed, first after `PreviousTransformSystem`) advances it with `MovingPlatformMath.Advance` (ping-pong, reflecting overshoot) and shifts riders by the same delta. A rider = grounded body whose feet are at the platform's old top with horizontal overlap. A platform rising into a body that was at/just above its top lifts it to the new top (otherwise the body ends up inside the solid and, per the sweep rules, falls through). Decisions: platforms stay `StaticSolid`s so `PhysicsSystem` needs no change; riders are shifted, not swept, so a platform can carry a rider into a wall and does not push bodies it hits from the side or above (place paths in open space); the path start is the entity's placed position, so scenes only set travel and speed.
- **Not yet**: one-way platforms, slopes, body-vs-body collision, depenetration, pushing/crushing by moving platforms.

## Tilemaps (`src/Engine.Tilemaps`)

- `TileLayer` stores tile ids in a `Dictionary<long, TileChunk>` of 16x16 chunks keyed by packed chunk coordinates; chunks appear when a tile is placed and vanish when empty. Cell (0,0) is bottom-left, Y up, negatives allowed (`cell >> 4` and `& 15` floor correctly). The renderer reads chunks through `TryGetChunkTiles` (a `ReadOnlySpan<int>`, no copies).
- `TileSet` = atlas texture handle + tile size/columns/rows/spacing/margin; ids are 1-based, row-major; per-tile `IsSolid`.
- Layers and tile sets are **assets** (`Assets.Add("layer/ground", layer)`), referenced from the `TileLayerRenderer` component by handle. The layer entity's `Transform` position is the world position of cell (0,0); its Z is draw depth. `TileLayer.TileSize` is world units per tile (art is 16 px drawn at 32).
- `TileLayerRenderSystem` collects layers for its pass (`foreground` flag), sorts by Z, asks `Camera2D.GetVisibleBounds` for the visible world box, converts to a chunk range, and submits one `SpriteDraw` per visible tile to the shared `SpriteBatch` (UV rect inset by 0.02 px to stop atlas bleeding). Cached per-chunk GPU meshes are a later optimisation.
- `TileGridBuilder.FromLayer(layer, tileSet, layerOrigin)` makes the physics `TileGrid` from the layer's used bounds and the tile set's solid flags.

## Animation (`src/Engine.Animation`)

- `AnimationClip` = pixel rects + fps + `AnimationLoopMode` (Loop/Once/PingPong); `GetFrameIndex(time, out finished)` is pure.
- `AnimationStateMachine` (shared asset): float parameters (booleans are 0/1), states (each a clip), and ordered transitions (`From` a state or any, `To`, conditions on parameters, optional `RequiresFinished`). First matching transition wins; any-state transitions never target the current state. One transition per update.
- `SpriteAnimator` component = machine handle, current state, state time, speed, finished flag, parameter array (create with `SpriteAnimator.Create`). `AnimationSystem` (frame group) advances time, evaluates transitions, writes `Sprite.Source`. Game systems write parameters first (sample: `HeroAnimationSystem` from `PhysicsBody`).

## Scenes and prefabs (`src/Engine.Scenes`)

- **File shapes** (camelCase, indented). Scene: `{ "version": 1, "entities": [ { "prefab": "optional.prefab.json", "components": { "Transform": { "position": { "x": 1 } } } } ] }`. A prefab file is the same entity shape (and may itself name a `prefab`, depth limit 16). Asset data files: `.layer.json` (rows of tile ids, top row first, plus `originX/originY` of the bottom-left cell), `.tileset.json` (texture name, tile size, solid ids), `.anim.json` (parameters, states with `grid` or `frames` clips, transitions with conditions by name).
- **Components**: `ComponentRegistry.Register<T>(name)` builds a `TypedComponentSerializer<T>` (System.Text.Json with `IncludeFields`, camelCase, enums as text, computed read-only properties skipped). Only registered components are saved; unknown names in files throw naming the component. Names are stable file names, independent of the C# type. `Runtime.EngineComponents.RegisterAll` registers the engine's ten; games add their own (sample: `Patrol`).
- **Assets by name**: `AssetHandleConverter<T>` writes `assets.NameOf(handle)` (or `null`) and reads via `assets.Load<T>(name)`, which returns cached/in-memory assets first and otherwise loads the file. So anything a scene refers to needs a registered `IAssetLoader<T>`.
- **Load is two-phase**: resolve prefab chains and parse every component into a ready-to-apply action first (errors surface here, world untouched), then create entities. Prefab override = `JsonMerge.Apply` (RFC 7386: objects merge recursively, arrays/scalars replace, `null` removes). Prefabs are cached assets; resolution works on `DeepClone`d copies so cached templates are never mutated.
- **Save** writes every entity in id order with its registered components (`SerializeEntity` returns a valid prefab body). Quick-save in the sample writes `saves/quicksave.scene.json` next to the exe; quick-load does `World.Clear()` then `LoadFile`.
- **Prefab links**: an entity created from a prefab (scene entry or `Instantiate`) gets a `PrefabLink { Prefab }` component (owned by Scenes, deliberately **not** registered, so it is never written as a component). `Save()` writes such an entity as `{ "prefab": name, "components": <only what differs> }`: the base is the prefab built in a scratch world and written through the same serializers (so equal values format alike), and `JsonMerge.Diff(base, current)` is the inverse of the merge patch (changed fields, whole arrays, `null` for a removed component or field; numbers compare by value). An unchanged instance is just `{ "prefab": name }`, and a saved instance keeps following later edits to its prefab for every field it did not override. `SerializeEntity` (the public one-entity method) still writes everything, because its job is authoring a new prefab. Cost: Save builds each distinct prefab once per call.
- **Limits**: no `Entity` references between components (not remapped), no scene-in-scene, an instance cannot be re-pointed to another prefab except by editing `PrefabLink`, a prefab file edited on disk is not picked up until the asset is reloaded (no hot-reload yet), no editor yet.

## Diagnostics and tools (`Engine.Core/Diagnostics`, `Engine.Core/Logging`, `Engine.Runtime/Inspector`)

- **Logging**: `Logger` (Core, no Silk.NET) filters by `MinimumLevel` (default Info) and fans each `LogEntry` (time, level, category, message) out to its `ILogSink`s; sink exceptions propagate (fail loudly). `Game.Log` is created with a `ConsoleLogSink` and a 500-entry `MemoryLogSink` (ring buffer, so memory stays constant) that feeds `LogPanel`. Decision: an instance owned by `Game` rather than a static `Log` class, so tests and tools can build their own loggers and sinks, and a file or editor sink is one `AddSink` away. The clock is injectable for exact timestamps in tests.

- **Profiler**: sections are registered once by name and timed by integer id (`Begin()` returns a tick count, `End(section, start)` adds to that frame's total). `BeginFrame()` rolls the totals into a 120-frame ring buffer per section. Sections that run several times per frame (fixed systems on a multi-step frame) sum. The clock is injected (`Func<long>` plus ticks per second) so tests use exact values. `SystemGroup.Profile(profiler, "Fixed")` resolves a `group/SystemType` section per system up front, so a profiled run allocates nothing. `Game` calls `BeginFrame()` at the start of `OnUpdate` and closes the `CPU frame` section at the end of `OnGui` (the last callback of a frame, so it also works with the overlay hidden; it excludes the vsync wait in the buffer swap).
- **Type-erased component access** (`World.Reflection.cs`): `GetComponentTypes`, `GetBoxed`, `SetBoxed`, `AddBoxed`, `Remove(entity, Type)` (pools gained `ComponentType`/`GetBoxed`/`SetBoxed`/`AddDefault`). They box and allocate, so they are for tools only. Structural ones respect the query lock; `SetBoxed`, like `Set`, is allowed mid-query.
- **Inspector**: `ComponentRegistry.Describe()` supplies name, type and a valid default value (`Register<T>(name, defaultValue)`, e.g. `Transform.Identity`) for the Add menu. `FieldEditor` draws one widget per type (boxed `object` in, changed flag out) and recurses into structs: public-field structs are edited in place on the box, positional record structs (`Rect`, `Color`) are edited per constructor parameter and rebuilt through the constructor. Quaternions go through `QuaternionMath` (Euler degrees, pitch clamped at +-90). The inspector copies the component out, edits, and writes back only when something changed.
- **Audio flow**: `Game.OnLoad` registers `AudioClipLoader` and creates the device with `OpenAlAudioDevice.TryCreate` (a missing OpenAL library or output device yields a `NullAudioDevice` whose `Description` explains why; the overlay shows it). `OnUpdate` calls `Audio.Update()` (frees finished voices). `OnClosing` disposes the device after `Unload` and before `Assets`. `Play` takes a free voice or steals the oldest (`VoicePool`), buffers upload on first play or `Preload`, and handles are generation-checked so a stale `VoiceId` never stops someone else's sound.

## Sample game rules (`samples/Platformer`)

- **Split of responsibilities**: `GameSession` (pure: lives, score, coins, clock, `GamePhase`) owns every rule and has no engine types. `InteractionSystem` (fixed group, after `PhysicsSystem`) only detects hero overlaps (`BoxCollider.GetBounds` / `Aabb.Overlaps`) with `Coin`, `Patrol` (the creature marker) and `Goal` entities and reports events to the session; removals go through a `CommandBuffer` after the queries. A stomp = hero moving down with its feet above the creature's middle; anything else is a hit (the hero is put back at `GameSession.RespawnPoint`, standing still, with its `PreviousTransform` cleared; the 1.5 s invulnerability covers whatever stands there; a hit that ends the run does not move it). `PlatformerGame.Flow.cs` ticks the session each frame, zeroes the hero's `PlatformerIntent` once the run is over, swaps the exit door art when the last coin is taken, blinks the hero while invulnerable, and restarts by `World.Clear()` + `Scenes.LoadFile` (the same path as quick-load, which also re-syncs the coin count from the coins left in the world).
- **Pause**: `Game.IsPaused` (engine) skips the frame and fixed system groups and does not advance the `FixedTimestep`, so no time is owed on resume; `Update`/`Draw`/`Hud` still run. The sample's `PauseMenu` (pure: selection wrap-around and labels, unit-tested) is driven by `PlatformerGame.Pause.cs` from `Update` (keys) and `Hud` (ImGui `Selectable`s, mouse hover/click); while paused `Update` returns early, so the session clock, restart key, quick-save and spawning are frozen too. Pausing is refused once the run has ended (Enter restarts).
- **Checkpoints**: a `Checkpoint { Reached }` component (registered, placed from `checkpoint.prefab.json`, three in the level) is touched by `InteractionSystem`, which raises the flag and calls `GameSession.ReachCheckpoint(position)` (the session only stores the point; the game moves the hero). `SetStart` sets the point at level load, restart and quick-load (the loaded spot counts as a checkpoint because the session is not saved). `Reached` is part of the saved component, so a quick-load keeps raised flags raised; `PlatformerGame.Flow.cs` swaps the flag art from it each frame like the door. Decision: respawn replaced the old knockback, because with knockback a hit left the hero standing in the danger; the cost is that an early hit sends you to the start.
- **High scores**: `HighScores` (pure ranking plus JSON file; best 5, ties rank below the older run, scores <= 0 never recorded) with `ScoreEntry`. `PlatformerGame.Scores.cs` loads `saves/highscores.json` (next to the exe, outside `Assets/`, like the quick-save) at start, submits a run once when its phase leaves Playing and saves only when it earned a rank; the end message lists the table. Decision: a damaged file is player data, so the game logs an Error and starts with an empty table instead of refusing to start (`HighScores.Load` itself still throws, naming the file); loading re-submits every entry so a hand-edited file is re-sorted and trimmed.
- **Content as data**: `coin.prefab.json` and `goal.prefab.json` plus scene entries that override only the position; `Coin` and `Goal` are registered components, so quick-save/load and the inspector handle them with no extra code. The locked/open door is two cells of `items.png`, chosen by setting `Sprite.Source`.
- **UI**: `Game.Hud()` (new hook, called every frame before the debug panels, so it survives F1) draws the status line and end message with ImGui windows flagged no-decoration/no-input; the font scale is set per window.

## Assets

`AssetManager` (Core) caches by normalised relative path per asset type, using registered `IAssetLoader<T>`s; `AssetHandle<T>` is a 1-based int id (0 = invalid) into a per-type `AssetStore<T>`. **Hot-reload**: `AssetManager.Reload(name, fullPath?)` re-runs the loader and swaps the result in under the same handle (load first, then swap, then dispose the old one, so a broken file throws and leaves the old asset); `AssetHotReloader` (Core) watches a folder with a `FileSystemWatcher` whose events only enqueue, and the game loop calls `Poll()` once per frame (reloading a texture calls GL, so it must run on the context thread): a file is reloaded after `QuietSeconds` (0.3) without further events (editors write in several steps), a locked file is retried up to `MaxAttempts`, files the game itself just wrote are skipped via `Ignore` (the editor does this when it saves a tile layer), and files that are not loaded assets (scenes, scratch files) are ignored. `Game.HotReloadRoot` (null = off; the sample returns its project `Assets` folder, which is not the copy beside the exe) turns it on, so editing art in the project updates the running game. Limits: consumers must look the asset up through its handle each use (sprites, tiles and layers do); something built from the old asset and kept (the hero animation machine copied into `HeroAnimationSystem`, the collision grid built from the ground layer) is not rebuilt until restart or Play. `Add(name, obj)` registers procedural assets. `Game.Assets` roots at `<exe dir>/Assets`; sample assets are copied there by `Platformer.csproj`. The manager owns and disposes `IDisposable` assets.

## Rendering pipeline

- **Post-processing** (`Engine.Rendering/PostProcessing`): `RenderTarget` = framebuffer object + `Texture2D` colour attachment (RGBA8, linear filter; `Resize` recreates it). `FullscreenQuad` draws one oversized triangle from `gl_VertexID` (no vertex buffer, only the empty VAO core profile requires), and its vertex source is shared by every effect, which supplies `vUv`. `PostProcessChain` owns two window-sized targets: `BeginScene` binds target 0 when any effect is enabled, `EndScene` runs the enabled effects ping-ponging between the targets, the last writing to framebuffer 0. A shader cannot read what it writes, hence two targets. Textures sampled from a target are not flipped: render and sample share GL's bottom-left origin. `Game` resizes the chain from the window's resize event, times it as the `Post process` profiler section and disposes it after `Unload`.
- **Effects**: `SinglePassEffect` (base: one shader, `SetUniforms` hook) for colour grade and vignette; `BloomEffect` implements `IPostEffect` itself (bright pass to a half-resolution target, N rounds of separable 9-tap Gaussian, composite). Settings are public properties; `Runtime/Inspector/PostEffectsPanel` edits them by reflection through `FieldEditor`.
- **Lighting**: `LightingEffect` (first in the chain) rebuilds a screen-sized light map each frame: clear to `Ambient`, then a `SpriteBatch` pass with `SpriteBlend.Additive` (blend `SrcAlpha, One`) draws one tinted radial-gradient quad per `Light2D` in view (gradient texture from `LightMath.BuildGradientPixels`, falloff `(1 - d^2)^2`), through the scene camera so lights align with sprites. The composite shader outputs `scene * lightMap * Exposure`. Decision: a light-map multiply rather than per-sprite lighting, because its cost does not grow with sprite count and the sprite renderer is untouched; the price is no shadows and no normal maps.

- World space: X right, Y up, Z draw order (larger = in front). `Camera2D` zoom 1 = 1 world unit per pixel; `GetViewProjection()` is row-vector `Matrix4x4`, uploaded to GL without transpose and used as `uViewProjection * vec4(pos, 1)`.
- `SpriteQuad.Write` (pure, tested) builds 4 vertices from a `SpriteDraw`; `SpriteBatch` fills a `SpriteVertex[]` (max 8192 sprites, 16-bit indices), uploads with `glBufferSubData`, draws with a static index buffer, flushing on texture change. Alpha blending on, depth test off. Built-in GLSL 330 shader in `SpriteShaderSource`.
- Texture space: (0,0) top-left, image row 0 is the top. Window framebuffer size is assumed equal to window size (inferred; not tested on high-DPI displays).
